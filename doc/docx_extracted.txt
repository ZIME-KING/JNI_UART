
产品开发需求书V1.0项目名称：车载中控系统底层服务封装（JNI/串口通信库）1. 项目背景基于 Realtek RTD1861 芯片的 Android 车载中控主机。硬件方案公司已提供 BSP 层，并开放了与 MCU 通信的串口设备节点 /dev/ttyS7（波特率 460800，8N1）。MCU 与 ARM 之间的通信协议已在文档 MCU-ARM_v2.xlsx、Radio_v2.xlsx、Public_v2.xlsx 中完整定义，包含车辆信号（ACC、车速、倒车等）、收音机（FM/AM 调频、RDS 信息）、系统升级等消息类型。由于项目时间紧张，我方不采用标准 Android Vehicle HAL 路线，而是采用 “直接读写串口 + JNI 封装” 的快速方案：将串口访问与协议处理封装在 Native 层，生成一个或多个 .so 动态库，供 Android Launcher 及上层 App 通过 Java/Kotlin 调用。该方案需要解决串口独占、多业务（收音机、车辆信号、升级）并发访问、协议完整性（建链、心跳、ACK、重传）等关键问题。将委托第三方公司完成该底层服务库的开发与交付。2. 技术方案概述2.1 总体架构Android Launcher / App        │ (Java/Kotlin)        │ 调用 SDK 接口        ▼┌───  ──────────────────┐│  Java SDK (AAR/JAR)                        ││  - 原始数据收发日志（Hex 格式）在 write 之前，将待发送的数据字节以十六进制字符串形式输出，一行完整帧。在 read 之后，将从串口读到的原始字节以十六进制字符串形式输出（建议每帧单独一行，如长度较大可截断但需保留首尾）。格式要求：TX len=XX, hex: XX XX XX ...；RX len=YY, hex: YY YY YY ...。6.2.3 协议帧解析日志每解析出一个完整帧（包括帧头、长度、序列号、帧类型、MsgType、Cmd、数据、校验和），至少输出：帧类型（FrameType）、MsgType、Cmd、序列号、数据长度、校验和是否通过。对于心跳帧、ACK 帧，单独输出标识。6.2.4 链路状态日志建链发起、超时、重试、成功、失败。心跳发送与接收：每次发送心跳及收到对应 ACK 时输出。链路断开检测及重连尝试。6.2.5 业务命令日志发送任何主动命令（如设置频率、搜索、设置背光）时，输出命令名称及参数。收到异步上报（如车速、倒车、收音机频率）时，输出解析后的业务数据。6.2.6 错误与异常日志任何系统调用失败，必须输出 strerror(errno) 和 errno 值。校验和错误、帧长度异常、无效 MsgType/Cmd 等协议异常。ACK 超时、重试次数达到上限。6.3 日志开关与动态控制必须实现编译期日志级别宏（如 LOG_LEVEL_DEBUG、LOG_LEVEL_INFO），方便我方在开发阶段开启 DEBUG，量产阶段关闭。建议实现运行时控制：通过 Android 系统属性（如 persist.carserial.log.level）动态调整日志级别，无需重新编译。示例：cint log_level = __system_property_get(&quot;persist.carserial.log.level&quot;, value);if (strcmp(value, &quot;DEBUG&quot;) == 0) enable_debug = 1;默认出厂配置为 INFO 级别，DEBUG 级别仅在开发/联调阶段开启。6.4 日志性能与安全要求DEBUG 级别的 Hex 日志不得影响串口读写实时性（建议使用异步日志缓存或仅在可控频率下输出）。生产版本（Release 编译）应移除或条件编译掉 DEBUG 级别日志，避免日志刷屏和泄露敏感数据。日志中不得包含用户隐私信息（如 GPS 坐标、设备唯一标识等），仅保留技术调试数据。6.5 验收时需提供的日志示例提供一份完整的 logcat 输出文件，覆盖以下场景：设备上电 → 建链 → 心跳 → 发送收音机调频命令 →
