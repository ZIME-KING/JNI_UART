# 常用命令（构建 / 运行 / 联调）

## Windows：安装依赖

```powershell
winget install Kitware.CMake -e
winget install --id Microsoft.VisualStudio.2022.BuildTools -e
```

Python 依赖（Windows 常见是 `pip` 不在 PATH，用下面更稳）：

```powershell
py -m pip install --upgrade pip
py -m pip install pyserial
```

## Windows：构建 Native Host Demo（carserial_host_tool.exe）

```powershell
cd C:\Users\95228\Desktop\JNI_UART
Remove-Item -Recurse -Force .\build\native-host -ErrorAction SilentlyContinue

$cmake="C:\Program Files\CMake\bin\cmake.exe"
& $cmake -S carserial/native -B build/native-host -G "Visual Studio 17 2022" -A x64
& $cmake --build build/native-host --config Release
```

运行：

```powershell
.\build\native-host\Release\carserial_host_tool.exe COM5 --baud 460800
```

常用参数：

```powershell
.\build\native-host\Release\carserial_host_tool.exe COM5 --help
.\build\native-host\Release\carserial_host_tool.exe COM5 --send-radio-freq 0 10170
.\build\native-host\Release\carserial_host_tool.exe COM5 --update-demo
```

## Windows：日志级别与 stderr

Windows 下默认会把 Native 日志打印到 stderr（同一个终端里能看到）。可手动设置日志级别：

```powershell
$env:CAR_SERIAL_LOG_LEVEL="DEBUG"   # DEBUG/INFO/WARN/ERROR
.\build\native-host\Release\carserial_host_tool.exe COM5
```

把 stderr 单独保存到文件：

```powershell
.\build\native-host\Release\carserial_host_tool.exe COM5 2> log_stderr.txt
Get-Content .\log_stderr.txt -Wait
```

## Windows：无 MCU 联调（mock MCU + 虚拟串口）

前提：准备虚拟串口对（例如 COM5 <-> COM6）。

终端 1（模拟 MCU，占用 COM6）：

```powershell
cd C:\Users\95228\Desktop\JNI_UART
py .\tools\mock_mcu.py --port COM6 --baud 460800
```

终端 2（Host Demo，占用 COM5）：

```powershell
cd C:\Users\95228\Desktop\JNI_UART
.\build\native-host\Release\carserial_host_tool.exe COM5 --baud 460800
```

## Windows：串口透明转发抓包（A<->B + Hex）

```powershell
cd C:\Users\95228\Desktop\JNI_UART
py .\tools\serial_forwarder.py --a COM5 --b COM6 --baud 460800
```

## Android：构建 Native 可执行文件（carserial_host_tool）

推荐用脚本（会同时构建 libcarserial.so 与 carserial_host_tool，并输出到 dist/bundle_*）：

```powershell
cd C:\Users\95228\Desktop\JNI_UART
powershell -ExecutionPolicy Bypass -File .\tools\package.ps1 -BuildHost 0 -BuildAndroidSo 1 -Zip 0 -AndroidAbi armeabi-v7a -AndroidApi 21
```

arm64 版本：

```powershell
cd C:\Users\95228\Desktop\JNI_UART
powershell -ExecutionPolicy Bypass -File .\tools\package.ps1 -BuildHost 0 -BuildAndroidSo 1 -Zip 0 -AndroidAbi arm64-v8a -AndroidApi 31
```

产物目录示例：

- `dist\bundle_YYYYMMDD_HHMMSS\android\bin\<ABI>\carserial_host_tool`
- `dist\bundle_YYYYMMDD_HHMMSS\android\jniLibs\<ABI>\libcarserial.so`

## adb：传输文件（push / pull）

```powershell
adb push dist\bundle_YYYYMMDD_HHMMSS\android\bin\armeabi-v7a\carserial_host_tool /data/local/tmp/
adb shell chmod +x /data/local/tmp/carserial_host_tool
adb pull /data/local/tmp/serial_log.jsonl .
```

## Android：运行例子（真机，默认 /dev/ttyS7）

```powershell
adb shell "/data/local/tmp/carserial_host_tool --baud 115200 --send-msg 0x01 0x80 --data-ascii PING --need-ack 0 --log /data/local/tmp/serial_log.jsonl"
```

覆盖默认端口（示例：/dev/ttyAS0）：

```powershell
adb shell "/data/local/tmp/carserial_host_tool /dev/ttyAS0 --baud 115200 --send-msg 0x01 0x80 --data-ascii PING --need-ack 0 --log /data/local/tmp/serial_log.jsonl"
```

只看 carserial 相关日志：

```powershell
adb logcat -c
adb logcat -s carserial:*
```
